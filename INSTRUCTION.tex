In this assignment, you will build your own motor imagery EEG (MI-EEG)
classification pipeline. You will design both an EEG
preprocessing/feature-extraction pipeline and a neural network,
integrate them into the existing repository, and compare your method
with \textbf{MixNet}.

To make the comparison fair, your method and MixNet must be evaluated
under exactly the same experimental protocol: the same 9 subjects, the
same 5-fold cross-validation procedure, the same test session, and the
same evaluation metrics.

\section{1. Learning Objectives}\label{learning-objectives}

By the end of this assignment, you should be able to:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\item
  \textbf{Build a reusable EEG pipeline.}
  Implement your preprocessing or feature-extraction method and neural
  network within the repository's existing experimental framework.
\item
  \textbf{Run a controlled benchmark.}
  Compare your proposed method with a strong published baseline under
  the same experimental conditions, and report the results
  transparently, including cases where your method performs worse.
\item
  \textbf{Interpret your results.}
  Go beyond reporting average performance. Examine the per-subject
  results together with the paired statistical test, identify patterns
  in the results, and propose reasonable explanations for what you
  observe.
\end{enumerate}

\subsection{The Most Important Rule: Prevent Data
Leakage}\label{the-most-important-rule-prevent-data-leakage}

\textbf{Any operation that learns parameters from the data must be
fitted using the training fold only.}

Examples include:

\begin{itemize}
\item
  CSP filters
\item
  PCA
\item
  normalization using dataset-level mean and standard deviation
\item
  whitening
\item
  channel selection
\item
  learned feature selection
\end{itemize}

These operations must be fitted inside \texttt{fit\_transform()} using
only the current training fold. The resulting fitted parameters should
be stored in \texttt{state} and then applied to validation and test
data inside \texttt{transform()}.

Fitting any of these operations on the full dataset before
cross-validation introduces data leakage and invalidates the
comparison with MixNet.

Stateless operations may be applied independently to each split.
Examples include:

\begin{itemize}
\item
  band-pass filtering
\item
  cropping
\item
  resampling
\item
  log-variance computation
\end{itemize}

\subsection{Possible Approaches}\label{possible-approaches}

You are free to design your own pipeline. Possible directions include:

\begin{itemize}
\item
  Filter bank + CSP using \texttt{mixnet.preprocessing.FBCSP}
\item
  Band-power or log-variance features for each channel and frequency
  band
\item
  Riemannian covariance features with tangent-space projection
\item
  STFT or wavelet time-frequency maps

Implement your model architecture and any model-specific configuration

\subsection{Model Contract}\label{model-contract}

Your model must satisfy the following interface:

\begin{itemize}
\item
  \textbf{Input:} one tensor with shape \texttt{self.input\_shape},
  excluding the batch dimension
\item
  \textbf{Output:} one tensor with shape:
\end{itemize}

\begin{verbatim}
(batch, num_class)
\end{verbatim}

\begin{itemize}
\item
  The final layer must be:
\end{itemize}

\begin{verbatim}
layers.Activation('softmax')
\end{verbatim}

\begin{itemize}
\item
  The model name must be:
\end{itemize}

\begin{verbatim}
name=self.model_name
\end{verbatim}

Do \textbf{not} name your model \texttt{MixNet} or \texttt{MIN2Net},
because \texttt{mixnet/models/base.py} contains special branches for
those model names.

Keep the provided \texttt{load\_weights} block. Otherwise,
\texttt{evaluate()} may silently evaluate an untrained model.

\subsection{First Make Sure the Pipeline
Works}\label{first-make-sure-the-pipeline-works}

Before building a more complex architecture, use the following minimal
model in \texttt{build()} and run one subject end to end:

\begin{verbatim}
input1 = layers.Input(shape=self.input_shape)

x = layers.Flatten()(input1)
x = layers.Dense(self.num_class)(x)

softmax = layers.Activation(
    'softmax',
    name='softmax'
)(x)

model = Model(
    inputs=input1,
    outputs=softmax,
    name=self.model_name
)
\end{verbatim}

Once the full pipeline works, replace this model with your actual
architecture.

You can use the following files as examples:

\begin{verbatim}
mixnet/models/EEGNet.py
mixnet/models/DeepConvNet.py
\end{verbatim}

Both follow the same model contract.

then you are responsible for updating all related components.

\subsection{How to Interpret the Results}\label{how-to-interpret-the-results}

\subsubsection{Per-subject performance}\label{per-subject-performance}

Do not rely only on the overall average.

BCIC2a contains substantial between-subject variability. A model may
achieve a higher overall mean while still performing worse than the
baseline for several subjects.

Examine which subjects improve and which subjects do not.

\subsubsection{Paired statistical test}\label{paired-statistical-test}

Use the paired t-test or Wilcoxon result together with the per-subject
table.

There are only 9 subjects, so statistical power is limited. A p-value
should therefore never be reported without also showing the underlying
subject-level results.

\subsubsection{Number of subject-level
wins}\label{number-of-subject-level-wins}

The output:

\begin{verbatim}

\subsection{You Are Not Required to Beat
MixNet}\label{you-are-not-required-to-beat-mixnet}

MixNet is a published model with tuned hyperparameters.

A careful, reproducible experiment that performs worse than MixNet but
is properly analysed is more valuable than an unexplained improvement
caused by data leakage or an unfair comparison.

The quality of your experimental design and analysis matters more than
simply obtaining the highest score.
